# Conversation Context

같은 `conversation_id`의 후속 명령은 이전 제약과 결과의 작은 요약을 참조한다. 전체 경로, 전체 후보 evidence, 이벤트 로그, 원문 명령 전체는 LLM Context에 넣지 않는다.

## 상속되는 값

- `warehouse_id`
- 대상 작업·대상 로봇 범위
- 로봇 수 제한
- 제외 로봇·노드·간선
- 포함 로봇과 고정 로봇 배정
- 최적화 우선순위와 가중치
- 활성 plan/simulation 참조
- 가상 시나리오 설정(실행 명령 제외)

후속 명령에 새 값이 있으면 해당 필드만 override한다. “R-02를 다시 포함”하면 제외 목록에서 제거한다.

`같은 조건에서`, `동일한 조건으로`, `아까 조건 그대로`, `같은 작업으로`,
`방금 작업을`, `이번에는 기준만 바꿔서`처럼 이전 범위를 참조하면 대상 작업과
대상 로봇 범위를 상속한다. 현재 명령에 새 작업 ID가 있으면 새 범위로 교체한다.

빈 배열은 기본적으로 “사용자가 범위를 명시하지 않음”으로 처리한다. `모든 작업으로
바꿔줘`, `작업 제한을 없애줘`, `전체 작업을 대상으로 해줘`처럼 명시적인 해제
표현이 있을 때만 대상 작업 범위를 빈 배열로 확정한다. 이전 범위를 참조했지만
저장된 대상 작업이 없으면 전체 작업으로 확대하지 않고 clarification을 요청한다.

## 상속하지 않는 값

- EXECUTE 승인
- RESET 승인
- 실제 운영 이벤트 반영 승인
- 이전 clarification 선택지
- 이전 명령 원문과 실패 원인

`EXECUTE`, `RESET`, 실제 이벤트 반영과 활성 계획 변경은 매번 명시해야 한다.

PostgreSQL의 `conversation_session`은 활성 상태와 compact summary를 저장하고, `conversation_command_link`는 순서와 부모 명령을 저장한다. 대화와 warehouse가 다르면 처리를 차단한다.
