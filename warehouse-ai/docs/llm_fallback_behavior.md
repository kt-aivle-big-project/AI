# LLM 실패 시 규칙 기반 처리 범위

현재 LLM 사용 범위는 변경하지 않습니다.

## 자연어 명령 해석

- LLM 연결이 정상이면 구조화된 `CommandInterpretation`을 생성합니다.
- LLM이 실패하거나 API 키가 없으면 규칙 파서가 이해할 수 있는 조회·명확한 계획
  명령은 규칙 결과로 대체합니다.
- 규칙 파서가 이해하지 못하는 복합 자연어는 임의로 계획하지 않고
  `INTERPRETATION_FAILED` 또는 추가 확인 상태로 종료합니다.

따라서 자연어 해석 fallback은 **지원되는 표현 범위 안에서만 가능**합니다.

## Supervisor 판단

- LLM 판단 실패 시 `deterministic_supervisor_decision()`을 사용합니다.
- LLM이 성공해도 명령 종류, 실행 방식, 필수 도구, 위험 경계는 규칙 결과로
  다시 제한합니다.

## 최종 검증

- 규칙 기반 검증 결과를 먼저 생성합니다.
- LLM 검증 실패 시 `deterministic_verification_decision()`을 그대로 사용합니다.
- LLM은 규칙이 통과시킨 계획에 새로운 실패를 만들거나, 규칙 차단 결과를 지울 수
  없습니다.

## 사용자 보고서

- LLM 보고서 실패 시 결정된 결과를 템플릿으로 출력합니다.
- LLM 보고서가 실제 계획의 핵심 사실을 보존하지 않으면 템플릿으로 대체합니다.

## 결론

- Supervisor, 최종 검증, 보고서: 규칙 기반 자동 대체 가능
- 자연어 해석: 규칙이 지원하는 표현만 자동 대체 가능
- 복잡한 명령을 규칙이 이해하지 못하면 안전하게 중단
